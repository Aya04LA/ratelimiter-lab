Four rate-limiting algorithms behind one Redis, side by side. Every button sends the same traffic to all four, so you can watch where they agree and where they don't.

How it works

  • Shared state, stateless app. All counters live in Redis, so you can add app instances and the limit stays global. That's what “Instances seen” is counting.
  • One atomic script per request. Each check is a single Lua script, so concurrent requests can't race between reading a counter and writing it. It's also one network round trip.
  • Fails open. If Redis goes down, traffic passes through (configurable) rather than taking the whole API down with it.
  • Standard headers. RateLimit-Limit, RateLimit-Remaining, RateLimit-Reset and Retry-After on every response.

Use it as a service

Any backend can ask whether a key may proceed, with its own rule:

curl -X POST /v1/check \
  -H 'Content-Type: application/json' \
  -d '{"key":"user:42","algorithm":"token_bucket",
       "limit":100,"window":60}'

{"allowed":true,"limit":100,"remaining":99,
 "reset_after":0.6,"retry_after":0.0}
